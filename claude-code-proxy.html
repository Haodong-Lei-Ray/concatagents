🛠️ Claude Code 转接口手术详解

目标：将 Claude Code 的请求从"直连 Anthropic 官方 API"改到"经第三方上游（聚合代理等）+ 本地智能路由 shim"；shim 支持多上游，不同模型自动路由到不同第三方后端。

📋 背景问题

PROBLEM Claude Code 有 5 个内置模型菜单项：
  1. 1. Default → 请求 claude-opus-4-7-1m（1M 上下文）
  2. 2. Sonnet → 请求 claude-sonnet-4-6
  3. 3. Sonnet (1M context) → 请求 claude-sonnet-4-6-1m
  4. 4. Haiku → 请求 claude-haiku-4-5（短名）
  5. 5. Opus 4.6 (Custom) → 请求 claude-opus-4-6（通过 ANTHROPIC_CUSTOM_MODEL_OPTION 配置）
PROBLEM 第三方聚合代理（35.220.164.252:3888）只支持这些模型：
  • ✅ claude-opus-4-7、claude-opus-4-6
  • ✅ claude-sonnet-4-6
  • ✅ claude-haiku-4-5-20251001（没有短名版本）
  • ❌ claude-opus-4-7-1m（代理没有 1M SKU）
  • ❌ claude-sonnet-4-6-1m
  • ❌ claude-haiku-4-5（短名，代理不认）

结果：菜单项 1、3、4 会报 model_not_found，只有 2 和 5 能工作。

💡 核心思路

Claude Code 是闭源的，我们没法改它的模型 id 逻辑。唯一的办法是：

SOLUTION 在 Claude Code 和第三方上游之间加一个本地 HTTP shim：按 model 前缀把流量分到第三方聚合代理或第三方 MiniMax（Anthropic 兼容）等后端，并在需要时自动做格式转换。

🏗️ 整体架构

┌────────────────────────────────┐ Claude Code ─HTTP──▶ │ 127.0.0.1:3889 (本地 shim) │ └───────────────┬────────────────┘ │ model 以 "minimax-" 开头？ │ ┌───────────┴───────────┐ │ YES │ NO ▼ ▼ 第三方 MiniMax 第三方聚合代理 Anthropic 兼容 API 35.220.164.252:3888 （可配置区域/域名） │ │ ▼ │ 上游已收录的 │ Anthropic/OpenAI 等 id │ ┌─────────┴──────────┐ │ 第三方路径上 │ │ 可能需格式转换 │ │（以 shim 为准） │ └────────────────────┘

📡 第三方双上游路由逻辑

shim 收到请求后，先解析 JSON body 里的 model 字段，然后分两条路：

条件 上游 格式转换 所需环境变量
model 以 minimax- 开头
且 MINIMAX_API_KEY 已设		 第三方 MiniMax
MINIMAX_ANTHROPIC_BASE_URL 所指 Anthropic 兼容端		 Anthropic ↔ 上游所需格式（双向，视实现而定） MINIMAX_API_KEY
MINIMAX_ANTHROPIC_BASE_URL（可选，有默认值）
其余 第三方模型 id
非 minimax- 前缀		 CLAUDE_PROXY_UPSTREAM
例：35.220.164.252:3888		 仅做 model alias 替换，其余原样透传给第三方聚合代理 CLAUDE_PROXY_UPSTREAM（可选，有默认值）
💡 第三方 MiniMax 路径的格式转换（若你的 shim 实现包含）：典型做法是把 Anthropic 请求体转成上游接受的格式再发第三方 MiniMax，响应再转回 Anthropic。具体字段/上限以你所部署的 shim 版本为准；旧版示例里曾描述 system 合并、<think>、max_tokens 截断等细节，部署时请对照当前 claude-model-proxy.js。

🧬 手术第一步：写本地 shim

FILE ~/.local/bin/claude-model-proxy.js
~/.local/bin/claude-model-proxy.js/** * claude-model-proxy * 本地 HTTP 代理，第三方双上游路由： * - minimax-* → 第三方 MiniMax（Anthropic 兼容端） * - 其他 id → 第三方聚合代理（仅 model alias，余下透传） */ const http = require("http"); const https = require("https"); const { URL } = require("url"); // 默认上游：第三方聚合代理 const UPSTREAM = new URL( process.env.CLAUDE_PROXY_UPSTREAM || "http://35.220.164.252:3888" ); // 监听端口 const LISTEN_PORT = Number(process.env.CLAUDE_PROXY_PORT || 3889); const LISTEN_BIND = process.env.CLAUDE_PROXY_BIND || "127.0.0.1"; // 第三方 MiniMax 上游（需 MINIMAX_API_KEY） const MINIMAX_API_KEY = process.env.MINIMAX_API_KEY || ""; const MINIMAX_BASE_URL = process.env.MINIMAX_BASE_URL || "https://api.minimaxi.com/v1"; let MINIMAX_UPSTREAM = null; // MINIMAX_API_KEY 未设置则禁用「第三方 MiniMax」分支 try { if (MINIMAX_API_KEY) MINIMAX_UPSTREAM = new URL(MINIMAX_BASE_URL); } catch (_) {} // 判断是否走第三方 MiniMax 分支 function isMiniMaxModel(modelId) { if (!modelId || !MINIMAX_UPSTREAM) return false; return modelId.toLowerCase().startsWith("minimax-"); } // 模型别名表：Claude Code id → 第三方聚合代理实际支持的 id（minimax-* 不走此表） const MODEL_ALIASES = { "claude-opus-4-7-1m": "claude-opus-4-7", // 菜单1 → opus-4-7 "claude-opus-4-6-1m": "claude-opus-4-6", // 菜单1（历史版） "claude-opus-4-5-1m": "claude-opus-4-5-20251101", "claude-sonnet-4-6-1m": "claude-sonnet-4-6", // 菜单3 → sonnet-4-6 "claude-sonnet-4-5-1m": "claude-sonnet-4-5-20250929", "claude-haiku-4-5": "claude-haiku-4-5-20251001", // 菜单4 → 带日期完整 id "claude-opus-4-5": "claude-opus-4-5-20251101", "claude-sonnet-4-5": "claude-sonnet-4-5-20250929", "claude-sonnet-4": "claude-sonnet-4-20250514", "claude-opus-4": "claude-opus-4-20250514", }; // ── 路由判断 ────────────────────────────────────────────────────── function rewriteBody(buf, contentType) { if (!buf || !buf.length) return { buf, from: null, to: null, isMiniMax: false }; if (!(contentType || "").toLowerCase().includes("application/json")) return { buf, from: null, to: null, isMiniMax: false }; let obj; try { obj = JSON.parse(buf.toString("utf8")); } catch (_) { return { buf, from: null, to: null, isMiniMax: false }; } if (!obj || typeof obj.model !== "string") return { buf, from: null, to: null, isMiniMax: false }; // 第三方 MiniMax 路由：原样透传 body（forwardToMiniMax 负责格式转换） if (isMiniMaxModel(obj.model)) return { buf, from: obj.model, to: obj.model, isMiniMax: true, body: obj }; // 默认路由：alias 后转发给第三方聚合代理 const mapped = MODEL_ALIASES[obj.model]; if (!mapped || mapped === obj.model) return { buf, from: null, to: null, isMiniMax: false }; const from = obj.model; obj.model = mapped; console.error(`[alias] ${from} -> ${mapped}`); // 日志 return { buf: Buffer.from(JSON.stringify(obj)), from, to: mapped, isMiniMax: false }; } // ── 转发请求（非第三方 MiniMax 分支）───────────────────────────────────────── // rw.isMiniMax === true 时由 forwardToMiniMax() 处理，此路径不执行 const lib = UPSTREAM.protocol === "https:" ? https : http; fwd = lib.request({ hostname: UPSTREAM.hostname, port: UPSTREAM.port, path: req.url, method: req.method, headers }, (upstream) => { res.writeHead(upstream.statusCode || 502, upstream.headers); upstream.pipe(res); }); fwd.end(rw.buf); // 发送改写后的请求（alias 已替换）

🔧 关键技巧总结

  1. 改请求体，不改 URL — Claude Code 发的是 HTTP POST JSON，把 model 字段从 JSON body 里改掉，比改 HTTP Header 更可靠。
  2. 只改认识的 id，未知 id 原样透传 — 典型第三方模型 id（例如 deepseek-v4-pro）不在别名表里时，shim 直接透传到 CLAUDE_PROXY_UPSTREAM；上游已收录该 id 即可工作。
  3. 第三方 MiniMax 分支的格式转换 — 若走 minimax-* 且已配置 MINIMAX_API_KEY，由 shim 与上游约定完成 Anthropic 兼容对话；Claude Code 侧仍只认 Anthropic 形态。
  4. 第三方 MiniMax 仅需密钥即可路由 — 在 systemd 或环境中设好 MINIMAX_API_KEY（及按需的 MINIMAX_ANTHROPIC_BASE_URL），shim 识别 minimax- 前缀并转发，对 Claude Code 透明。
  5. stdout → stderr 打日志 — shim 里用 console.error() 写日志，这样不会干扰 HTTP 响应数据，同时可以通过 journalctl 实时看到每次改写。
  6. systemd 守护 — 用 user systemd service 管理 shim，崩溃后 3 秒自动重启，开机自启，不用手动盯着。
  7. 进程 env 是一次性的 — ~/.bashrc 改了之后，已启动的 Claude Code 进程不会自动更新，必须 source ~/.bashrc 或重启进程。
