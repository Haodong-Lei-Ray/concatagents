🛠️ Claude Code 转接口手术详解

目标：将 Claude Code 的请求从"直连 Anthropic 官方 API"改到"走我们自己的第三方代理 + 本地智能路由 shim"；shim 支持多上游，不同模型自动路由到不同后端。

📋 背景问题

PROBLEM Claude Code 有 5 个内置模型菜单项：
  1. 1. Default → 请求 claude-opus-4-7-1m（1M 上下文）
  2. 2. Sonnet → 请求 claude-sonnet-4-6
  3. 3. Sonnet (1M context) → 请求 claude-sonnet-4-6-1m
  4. 4. Haiku → 请求 claude-haiku-4-5（短名）
  5. 5. Opus 4.6 (Custom) → 请求 claude-opus-4-6（通过 ANTHROPIC_CUSTOM_MODEL_OPTION 配置）
PROBLEM 第三方代理（35.220.164.252:3888）只支持这些模型：
  • ✅ claude-opus-4-7、claude-opus-4-6
  • ✅ claude-sonnet-4-6
  • ✅ claude-haiku-4-5-20251001（没有短名版本）
  • ❌ claude-opus-4-7-1m（代理没有 1M SKU）
  • ❌ claude-sonnet-4-6-1m
  • ❌ claude-haiku-4-5（短名，代理不认）

结果：菜单项 1、3、4 会报 model_not_found，只有 2 和 5 能工作。

💡 核心思路

Claude Code 是闭源的，我们没法改它的模型 id 逻辑。唯一的办法是：

SOLUTION 在 Claude Code 和上游代理之间加一个本地 HTTP shim，按 model 前缀智能路由到不同后端（第三方代理 或 MiniMax API），并自动做格式转换。

🏗️ 整体架构

┌────────────────────────────────┐ Claude Code ─HTTP──▶ │ 127.0.0.1:3889 (本地 shim) │ └───────────────┬────────────────┘ │ model 以 "minimax-" 开头？ │ ┌───────────┴───────────┐ │ YES │ NO ▼ ▼ api.minimaxi.com 35.220.164.252:3888 /v1/chat/completions (第三方代理) (OpenAI 格式) │ │ ▼ │ Anthropic / OpenAI │ 官方 API │ ┌─────────┴──────────┐ │ 双向格式转换 │ │ Anthropic ↔ OpenAI │ └────────────────────┘

📡 双上游路由逻辑

shim 收到请求后，先解析 JSON body 里的 model 字段，然后分两条路：

条件 上游 格式转换 所需环境变量
model 以 minimax- 开头
且 MINIMAX_API_KEY 已设		 api.minimaxi.com/v1 Anthropic → OpenAI → Anthropic（双向） MINIMAX_API_KEY
MINIMAX_BASE_URL（可选，有默认值）
其他所有模型 35.220.164.252:3888 仅做 model alias 替换，请求直透 CLAUDE_PROXY_UPSTREAM（可选，有默认值）
💡 MiniMax 格式转换细节：shim 把 Anthropic 格式（system + messages）转成 OpenAI Chat Completions 格式发给 MiniMax，收到响应后再转回 Anthropic 格式。多条 system 消息会合并为一条（MiniMax 限制）；支持 <think> 标签提取为 thinking 内容块；max_tokens 上限截断为 8192。

🧬 手术第一步：写本地 shim

FILE ~/.local/bin/claude-model-proxy.js
~/.local/bin/claude-model-proxy.js/** * claude-model-proxy * 本地 HTTP 代理，智能路由到不同上游： * - minimax-* 模型 → MiniMax API（含 Anthropic↔OpenAI 格式转换） * - 其他模型 → 第三方代理（仅做 model alias 替换） */ const http = require("http"); const https = require("https"); const { URL } = require("url"); // 默认上游：第三方代理 const UPSTREAM = new URL( process.env.CLAUDE_PROXY_UPSTREAM || "http://35.220.164.252:3888" ); // 监听端口 const LISTEN_PORT = Number(process.env.CLAUDE_PROXY_PORT || 3889); const LISTEN_BIND = process.env.CLAUDE_PROXY_BIND || "127.0.0.1"; // MiniMax 上游（需要设置 MINIMAX_API_KEY 才会启用） const MINIMAX_API_KEY = process.env.MINIMAX_API_KEY || ""; const MINIMAX_BASE_URL = process.env.MINIMAX_BASE_URL || "https://api.minimaxi.com/v1"; let MINIMAX_UPSTREAM = null; // MINIMAX_API_KEY 未设置则禁用 MiniMax 路由 try { if (MINIMAX_API_KEY) MINIMAX_UPSTREAM = new URL(MINIMAX_BASE_URL); } catch (_) {} // 判断是否路由到 MiniMax function isMiniMaxModel(modelId) { if (!modelId || !MINIMAX_UPSTREAM) return false; return modelId.toLowerCase().startsWith("minimax-"); } // 模型别名表：Claude Code 发出的 id → 第三方代理实际支持的 id（对 MiniMax 模型无效） const MODEL_ALIASES = { "claude-opus-4-7-1m": "claude-opus-4-7", // 菜单1 → opus-4-7 "claude-opus-4-6-1m": "claude-opus-4-6", // 菜单1（历史版） "claude-opus-4-5-1m": "claude-opus-4-5-20251101", "claude-sonnet-4-6-1m": "claude-sonnet-4-6", // 菜单3 → sonnet-4-6 "claude-sonnet-4-5-1m": "claude-sonnet-4-5-20250929", "claude-haiku-4-5": "claude-haiku-4-5-20251001", // 菜单4 → 带日期完整 id "claude-opus-4-5": "claude-opus-4-5-20251101", "claude-sonnet-4-5": "claude-sonnet-4-5-20250929", "claude-sonnet-4": "claude-sonnet-4-20250514", "claude-opus-4": "claude-opus-4-20250514", }; // ── 路由判断 ────────────────────────────────────────────────────── function rewriteBody(buf, contentType) { if (!buf || !buf.length) return { buf, from: null, to: null, isMiniMax: false }; if (!(contentType || "").toLowerCase().includes("application/json")) return { buf, from: null, to: null, isMiniMax: false }; let obj; try { obj = JSON.parse(buf.toString("utf8")); } catch (_) { return { buf, from: null, to: null, isMiniMax: false }; } if (!obj || typeof obj.model !== "string") return { buf, from: null, to: null, isMiniMax: false }; // MiniMax 路由：原样透传 body（forwardToMiniMax 负责格式转换） if (isMiniMaxModel(obj.model)) return { buf, from: obj.model, to: obj.model, isMiniMax: true, body: obj }; // 默认路由：做 alias 替换后转发给第三方代理 const mapped = MODEL_ALIASES[obj.model]; if (!mapped || mapped === obj.model) return { buf, from: null, to: null, isMiniMax: false }; const from = obj.model; obj.model = mapped; console.error(`[alias] ${from} -> ${mapped}`); // 日志 return { buf: Buffer.from(JSON.stringify(obj)), from, to: mapped, isMiniMax: false }; } // ── 转发请求（非 MiniMax）───────────────────────────────────────── // rw.isMiniMax === true 时由 forwardToMiniMax() 处理，此路径不执行 const lib = UPSTREAM.protocol === "https:" ? https : http; fwd = lib.request({ hostname: UPSTREAM.hostname, port: UPSTREAM.port, path: req.url, method: req.method, headers }, (upstream) => { res.writeHead(upstream.statusCode || 502, upstream.headers); upstream.pipe(res); }); fwd.end(rw.buf); // 发送改写后的请求（alias 已替换）

🔧 关键技巧总结

  1. 改请求体，不改 URL — Claude Code 发的是 HTTP POST JSON，把 model 字段从 JSON body 里改掉，比改 HTTP Header 更可靠。
  2. 只改认识的 id，未知 id 原样透传 — deepseek-v4-pro 不在别名表里，shim 就直接透传到上游，上游有这个模型所以能正常工作。
  3. MiniMax 双向格式转换 — MiniMax 不支持 Anthropic 格式，shim 在内存里做完整的 Anthropic→OpenAI 转换再发请求，收到后再转回，Claude Code 完全感知不到。
  4. MiniMax 只需 Key，无需改 Claude Code 配置 — 在 systemd service 里设好 MINIMAX_API_KEY，shim 自动识别 minimax- 前缀并路由，对 Claude Code 透明。
  5. stdout → stderr 打日志 — shim 里用 console.error() 写日志，这样不会干扰 HTTP 响应数据，同时可以通过 journalctl 实时看到每次改写。
  6. systemd 守护 — 用 user systemd service 管理 shim，崩溃后 3 秒自动重启，开机自启，不用手动盯着。
  7. 进程 env 是一次性的 — ~/.bashrc 改了之后，已启动的 Claude Code 进程不会自动更新，必须 source ~/.bashrc 或重启进程。
